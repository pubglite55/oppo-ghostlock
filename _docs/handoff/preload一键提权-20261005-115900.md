## 已做决策
- **两阶段 + 每阶段一个进程**：因为「一进程一写」铁律，两次 arb 写（SELinux、cap_effective）不能同进程完成。
- **用 `PSELECT_CAPS_MODE`（CAPS-ONLY）而非指针换 init_cred**：只动 `cap_effective`，避开 OPPO 守护对 uid/euid/gid 下降沿的检测。
- **root 子进程 `execve` 原始命令行**：这样提权体现在调用者自己的进程里（`toybox id` 自己打印 uid=0），而不是只在 exploit 子进程里。
- **日志改道到文件**：`pr_*` 用 `printf` → stdout，会在 autopwn 模式下污染 `id` 的输出。
- 默认 caps 值仍是 `0xC0`（`CAP_SETGID|CAP_SETUID`，提权够用、有实证）；`0x2100C0`（补 `CAP_SYS_MODULE`）仅为 KernelSU 预留、**未验证**。
