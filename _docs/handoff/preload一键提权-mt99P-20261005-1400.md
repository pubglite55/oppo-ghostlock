## 已做决策
- 阶段推进**不再用 execve**，改 worker + park；调用者只编排。
- 完成信号用 **pipe fd**（文件通道在提权后必然失效）。
- 未打中的 worker 可回收，**打中过的 worker 必须 park**。
- 取证只走 **host 侧流式**（设备侧 fsync 不可信）。
- 运行前等 **load 收敛（<12）**：trigger 对负载敏感（load 200+ 时 0 发）。

## 未决问题
1. **KernelSU Live（首要）**：`main.c` 里 `PSELECT_EXEC_TARGET` 的 hand-off 在 `mt97 finit_module` /
   `mt96 ksud` **之前** ⇒ root 路径永远走不到它们。且 CAPS 写法写入的是**指针值**，
   `CAP_SYS_MODULE(bit16)` 是否置位取决于该地址的位（`PSELECT_CAPS_OFF=2100C0` 的加法不能确定性控制）——
   需确定性构造含 bit16/bit21 的写值，或换一条不依赖 caps 的装载路径。
2. **每次 fired write 后仍有 30~38s 瞬态 `workqueue lockup`**（`pool cpus=1`，自行恢复）：
   这是 run B 里把 watchdog 打起来的同一通道，是设备健康上最后一处硬伤。
3. trigger 对负载敏感：成功那发 stage 1 试到第 3 次才打中。
4. `preload.so/preload29.so` 等损坏 inode 无法清理（除非 format 或换名）。
