# preload 一键提权 — mt99R 冻结记录（2026-10-05 晚）

本轮把「零环境变量一条命令拿 root」从"能跑"推进到**可复现 + 机理清楚**，
并把 `KernelSU Live` 的最后一层障碍**从推测变成实测结论**。

## 一、本轮新增/修复（代码）

| 标记 | 文件 | 内容 |
|---|---|---|
| mt99M | `main.c` | `finit_module` 前 `lseek(kfd,0,SEEK_SET)` + `fstat` 尺寸日志。根因：ksud 子进程与父进程**共享同一 file description**，`ksud insmod /proc/self/fd/<ko>` 把模块 fd 读到 EOF，父进程随后 `finit_module` 读到 **0 字节** ⇒ 内核回 `ENOEXEC`（伪装成"模块坏了"）|
| mt99M | `preload.c` | `PSELECT_KO` 改 `overwrite=0`（外部模块可覆盖默认路径，便于换模块测试）|
| mt99M | `main.c` | `PSELECT_KO_FLAGS` 可配（默认 3 = IGNORE_MODVERSIONS\|IGNORE_VERMAGIC；**0 = 让内核说出真实拒收理由**）——这是本轮拿到决定性判词的钥匙 |
| mt99N/mt99R | `main.c` | **`CAP_SYS_MODULE`(bit16) 确定化**：caps 值 = `page_base + caps_off`，而 `page_base` 是 32K 对齐的 order-3 slab ⇒ 它对 64K 取模只有 `0`/`0x8000`。**只接受自身 bit16=1 的 slab**（值固定在 `slab+0xC0` = 我们喷过的第一页），否则重泄漏（`PSELECT_PAGE_RETRY16`，默认 4）。**不要用 `+0x8000` 位移去强行翻 bit16**——那会把 rb_erase 的 8 字节 STORE 推到 slab 上半页（可能没被喷过）⇒ 设备复位 |
| mt99O/mt99P | `slide.c`/`common.h`/`preload.c` | `slide_trigger_touched()`（= `sched_ok>0 \|\| canary_hits>0`）作为**"本发到底触发过没有"的权威判据**；worker 通过继承管道回传；coordinator 据此决定「回收未中毒 worker 并重试」还是「已触发 ⇒ 必须 park」。`ap_wait_stage2()` 把"等结果"和"读回传"合成同一个轮询（消除时序赛跑），等待 300s + 每 30s 进度心跳 |

## 二、配方（本轮实证有效）

**每一发之前必须做的两件事**（缺一不可，实测）：

1. **软重启**（`svc power reboot`）：必须从 **Enforcing** 起步 ⇒ stage-1 会先跑 ⇒ 它那轮 prep 同时"热"了堆。
   实测：设备已是 Permissive 时跳过 stage-1 ⇒ stage-2 冷启动 ⇒ **连续 `sched_ok=0`**。
2. **内存预处理**：`am kill-all` + `cmd activity kill-all` + 关键 app `force-stop`，确认 `MemFree` 充足。
   实测：没做时连 stage-1 都不武装（`sched_ok=0`、`calls=1`、`[-] slide bad leaked pointer=...`）；
   补上后同配方直接跑出 `sched_ok=1 → uid=0(root)`。

成功命令（部署名见下）：

```bash
adb shell "PSELECT_KSUD=<manager libksud.so 路径> PSELECT_KO_FLAGS=0|3 PSELECT_STAGE2_RETRY=1 \
  TMPDIR=/dev LD_PRELOAD=/data/local/tmp/preloadP2.so /system/bin/toybox id"
```

## 四、KernelSU Live 的决定性结论 ⭐

在本机实测（caps 已确认充足：`CAP_SYS_MODULE(16)=1`）：

```
finit_module(fd=5 preopened, flags=0) ret=-1 errno=2 (No such file or directory)   ← ENOENT = Unknown symbol
finit_module(fd=8 preopened, flags=3) ret=-1 errno=8 (Exec format error)          ← ENOEXEC
```

- `flags=0`（内核**强制**检查 vermagic/modversions）走到 **符号解析** 才失败 ⇒ **内核接受了 ELF，卡在"找不到模块需要的符号"**
- 两个 LKM 都是 **GKI 内核**编的：tiann `vermagic=5.10.252-dirty`、RKSU `vermagic=5.10.245-dirty`
- 本机是**厂商内核** `5.10.236-android12-9-o-g74d132f4467a` ⇒ **符号集/布局都不同**

⇒ **现成的 GKI LKM（KernelSU / RKSU / ReSukiSU）在这台机器上永远装不进**。
⇒ 想 KernelSU Live，**唯一路径 = 用 OPPO 该机型的内核源码自编 LKM**（symbol 与 layout 都对得上）。

这也回填解释了上一会话为何只看到 caps 问题：那时连 caps 都过不了，这层错误根本不可见。
